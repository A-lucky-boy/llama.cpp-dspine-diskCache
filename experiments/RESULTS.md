# D1–D4 解码实验记录

实测日期：2026-11-15。硬件：RTX 4070 Ti SUPER 16GB (CUDA0) + RTX 3090 24GB (CUDA1)。
模型：Qwen3.8-27B-pi-Q4_K_M + Qwen3.8-27B-DSpine-b16-Q4_K_M，`-np 1`，`-c 262144`，KV `q4_0/q4_0`。

## 方法

- 语料：`E:\小说\正文.md`（155535 字中文散文，约 1.406 字/token）。取前缀构成长度递增的 prompt，模拟真实会话增长。
- 计时来源：服务端返回的 `timings`，不解析日志。每个配置先发一次预热请求（吸收 CUDA graph 构建）。
- 每个尺寸发两次相同请求：第一次冷 prefill，第二次命中提示缓存后测 128 token 解码（`temperature=0`）。
- 关键指标：
  - `per_round = predicted_ms / (draft_n / n_max)`，一轮草稿+校验的耗时，**不受接受率波动影响**；
  - `mean_len = predicted_n / rounds`，每轮产出 token 数；
  - 两者相除即 `ms/token`。投机解码的盈亏平衡点是 `mean_len > per_round / t_nospec`。

## 结果

### 解码（`temperature=0`，128 token）

| 配置 | 6K ctx | 33K ctx | 90K ctx | per_round 6K/33K/90K | mean_len |
|---|---|---|---|---|---|
| base（n_max 15，草稿 CUDA1） | 39.7 t/s / 25.17 ms | 46.9 / 21.33 | 35.3 / 28.33 | 59.9 / 68.6 / 80.1 | 2.38 / 3.22 / 2.83 |
| **d1：`--spec-type none`** | 37.4 / 26.76 | 30.9 / 32.35 | 22.8 / 43.83 | — | — |
| d2：n_max 6，草稿 CUDA1 | 42.8 / 23.34 | 46.1 / 21.68 | 36.5 / 27.40 | 56.2 / 63.5 / 74.9 | 2.41 / 2.93 / 2.73 |
| **d2b：n_max 6 + 草稿 CUDA0** | **43.9 / 22.79** | **48.7 / 20.55** | **37.3 / 26.83** | **54.9 / 60.2 / 73.3** | 2.41 / 2.93 / 2.73 |
| d3：目标模型单卡 3090，无投机 | 40.0 / 24.98 | 33.1 / 30.26 | 24.4 / 40.98 | — | — |

d4（ub 2048）解码 per_round 59.4/67.1/76.1，与 base 无差异（ub 不参与解码路径），其 90K 行的 73.2 t/s 是 mean_len 偶然升到 5.57 的采样噪声，不作结论依据。

## 结论

### D1：投机解码是赚的，但只在长上下文赚得多 —— 推翻"净零"的初判

无投机实测 26.76 / 32.35 / 43.83 ms/token，与此前用带宽模型估的 20.3 ms 差 32%，**带宽模型低估了真实开销**。
按实测值，投机的实际收益为 **1.06× / 1.52× / 1.55×**（6K / 33K / 90K）。盈亏平衡 mean_len 为 2.24 / 2.12 / 1.83，实测 mean_len 2.38–3.22 全部高于平衡点。
**行动：保留投机解码，不要关。**

### D2：n_max 6 + 草稿移 CUDA0，唯一有效的改动

- per_round 从 59.9/68.6/80.1 降到 54.9/60.2/73.3，**稳定降 8%–11%**，mean_len 基本不变 → 收益是干净的。
- 端到端 43.9/48.7/37.3 t/s，相对 base +9.8% / +2.6% / +5.7%。
- 附带收益：草稿模型 1.26 GB 从 3090 移走，CUDA1 占用 20.4 GB → 18.3 GB，为长上下文 KV 或磁盘缓存计划留出 2.1 GB。
- 只改 `n_max` 而不移卡（d2）收益只有 6%–7%，说明草稿在 3090 上与目标模型的 62% 层争带宽是真实存在的。

### D3：单卡 3090 否掉

无投机下单卡只比双卡快 **7%**（24.98 vs 32.35 vs 40.98 ms，对应 26.76/32.35/43.83），远低于带宽模型预期的 15%。
且 prefill 明显更差（90K 时 849 t/s 对双卡的 1208 t/s），因为 prefill 是算力受限，双卡才有优势。
单卡 + 投机更不可行：256K 上下文已占 21.9 GB，塞不下 1.26 GB 草稿；按 per_round 推算每轮约 25+36 = 61 ms，劣于 d2b 的 55 ms。
**行动：维持 `-sm layer -ts 38,62` 双卡布局。**

### D4：ub 保持 1024

2048 在双卡层切分下冷 prefill 慢 10%（1258 vs 1397 t/s），512 与 1024 持平。
**行动：不动 `-b 4096 -ub 1024`。**

## 建议落到部署脚本的两处改动

`start-localModel-dspine.ps1`：

```powershell
"--spec-draft-n-max", "6",          # 原 15
"--spec-draft-device", "CUDA0",     # 原 CUDA1
```

预计生产解码速度 +5%–10%，3090 释放 2.1 GB 显存。

## 待验证（不属于 D1–D4）

per_round 的固定开销约 36 ms，且从 n_max 15 降到 6 只减少 5 ms —— 说明开销主体不是校验位置数，而是草稿 block（`block_size=16` 由模型决定）+ `n_extract=5` 的目标特征导出。下一次要压这块，可试 `--spec-draft-swa`、`p_min`（当前 0.00）以及草稿 KV 降阶；但这些都会改变签名或需要重新做接受率对照。
